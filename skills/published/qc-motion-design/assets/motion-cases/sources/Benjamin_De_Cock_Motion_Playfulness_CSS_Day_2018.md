## 一、引言

大家好，感谢邀请。很高兴能在这里谈论设计与用户体验——这在几年前还不是大多数开发者和公司关注的话题。我叫 Benjamin，是 Stripe 的设计师。Stripe 是一家在线支付公司，设计在我们的文化中极为重要。我同时也是 CSS 工作组的成员，负责推进 CSS 规范、修复 bug、编写测试等工作。

CSS 的真正含义？我确信它代表的是"**迷人的细微惊喜**"（Charming Subtle Surprises）——这恰好就是今天的主题。

## 二、为什么设计很重要？

这场演讲的核心是：**如何打造令人愉悦的用户界面，让设计成为产品开发流程的核心**。

设计不只是美观，它是真实的商业竞争力。设计指数研究（Design Index Study）追踪了富时股票交易所上市公司十年的投资回报，结论非常清晰：**以设计为核心的公司，股价表现比其他公司高出超过 200%**。

软件行业已经发生了根本性转变。仅仅"解决问题"已经不够了——你必须打造一个**用户真正热爱使用**的产品。用户留存、满意度、参与度，这些都是长期业务的核心。现在，"提供丰富且快速的界面"几乎已经是新应用的基本门槛。

## 三、如何走这"额外一英里"？

### 3.1 小交互，大不同

以一个反馈组件为例：传统的反馈表单繁琐无趣，而一个允许用户点击 emoji 并立即看到动画响应的反馈组件，则让整个体验变得有趣且自然。支持拖拽选择时，表情随手指滑动而实时变化——这就是**动效与交互设计带来的乐趣感**。

## 四、动效设计：以 Stripe Connect 落地页为例

### 4.1 动态图标：让隐喻更准确

页面上的图标不是静态的，而是通过动画赋予了生命：
- 第一个图标使用 `requestAnimationFrame` 驱动 SVG 动画；
- 第二个使用 Web Animations API；
- 第三个使用 WebGL 实现真正的 3D 旋转效果。

以"全球化"图标为例：静态图标只能展示部分国家，无法传达"真正全球"的概念。**旋转动画本身解决了一个设计问题**——它不只是酷，它让图标的含义更准确。

### 4.2 动画的核心价值：连接状态

点击播放按钮时，三张静态预览图不是突然消失，而是平滑形变并展开成视频——这就是**连接状态（Connecting States）**，动效最重要的功能：

> 将用户行为与界面结果建立清晰、可预期的逻辑关联。

没有动效的界面，A 状态和 B 状态之间没有关系；有了动效，用户触发的操作引发的界面变化变得**可预期、可理解、有迹可循**。

### 4.3 帮助用户理解流程

- 支付流程图表：在不同选项间切换时以动画过渡，用户能清晰感知"什么变了、什么没变"；
- Connect 业务流程演示：用代码驱动的动画（而非视频）展示，整个动画加图片脚本仅约 **5KB**，分辨率无关、响应式友好；
- 页面上所有设备（3D 笔记本、手机等）均用代码实现，目标一致：**轻量、快速、响应式、可本地化**。

## 五、技术即设计：前端工艺的力量

### 5.1 代码作为设计工具

- **Apple Pay 页面**：底部指南针图标，在手机上倾斜设备时，指南针实时响应——这是用代码创造的真实交互；
- **Elements 页面插图**：看似普通的插图，实际上可以直接选中并复制粘贴，得到的是真实可用的代码实现——**让内容本身成为工具**，这才是真正的"走额外一英里"。

### 5.2 渐进式图像加载

环境页面的大尺寸头图问题：图片较重，但不想让用户看到空白。解决方案：

1. 将图片重绘为 **响应式 SVG 矢量插图**，直接内联进 HTML（无 HTTP 请求，无延迟）；
2. 用 CSS 滤镜对 SVG 添加**精心设计的模糊效果**（不是低分辨率放大，而是真正的设计级模糊）；
3. 实际图片加载完成后，平滑淡入覆盖 SVG；
4. SVG 随即从 DOM 中移除。

结果：**零加载延迟感，慢速网络下也有良好体验**。

### 5.3 条纹生成器：用代码解放设计创意

Stripe 品牌标志性的倾斜条纹很难手动设计——颜色随机、位置随机、组合太多。于是内部构建了一个条纹生成器：设置背景色、条纹颜色、样式尺寸，点击按钮批量生成方案，满意后直接复制 CSS/HTML 代码。

> 设计真正有趣的时刻，是你能引入**恰到好处的视觉噪点**。完全整洁不够好，完全混乱很糟糕，魔力在于"完美的混乱"——而这正是工具擅长的。

## 六、动效最佳实践

### 6.1 设计层面

#### ① 动效要有用
允许有纯粹为让用户微笑的视觉点缀——让人开心本身就是有用的。但要抵制滥用冲动。**当动效被用在错误的地方，它会拖慢交互、阻碍工作流**。

典型反例：为了炫技而劫持滚动（scroll hijacking）——这是最糟糕的设计决策之一。

正面案例：Radar 页面的 3D 球体动画基于滚动位置触发，但从不打断用户的滚动流程。

⚠️ **iOS 11 计算器案例**：按键加入了淡出动画，但动画期间触摸事件被屏蔽。快速输入"1+2+3"可能得到"24"——这就是动效干扰工作流的严重后果。

#### ② 尊重用户偏好
macOS 的"减少动态效果"（Reduce Motion）偏好设置应被 CSS 媒体查询检测并响应。即使动画很克制，对某些用户（如前庭功能障碍者）仍可能太多。

```css
@media (prefers-reduced-motion: reduce) {
  /* 减少或停止动画 */
}
```

#### ③ 让动效感觉快速
**感知速度远比实际性能重要**。一个加载动画转得更快，用户就会觉得 App 加载更快——即使两者实际加载时间完全相同。

#### ④ 精心设计缓动曲线（Easing）
不要使用默认的内置缓动，加速度不够强。**绝对不要用 linear（线性）缓动**——那是对动效设计的侮辱。

- 将缓动函数定义为 **CSS 自定义属性**，像使用标准关键词一样方便；
- 仅靠切换到更好的缓动曲线，动画质感会提升一倍。

**缓动选择指南：**

| 缓动类型 | 适用场景 |
|---|---|
| **ease-out**（先快后慢） | 最常用。元素出现、弹窗打开——立即给用户反馈，感觉响应迅速 |
| **ease-in-out**（先慢后快再慢） | 元素已在屏幕上，发生位置/形状变化。类似现实物体运动（如汽车） |
| **ease-in**（先慢后快） | 元素消失时。使用场景少，开头缓慢通常令人沮丧 |
| **linear**（线性） | 99% 的情况应避免。唯一例外：无交互的持续自动滚动内容 |

### 6.2 开发层面

#### ① 只动 `opacity` 和 `transform`
这两个属性是 CSS 中**可以高性能动画的属性**，能让浏览器走合成器路径，不触发重排重绘，最容易达到稳定 60fps。

> 稳定的 30fps 动画，比时常掉帧的 60fps 动画观感更好。

几乎所有常见动画效果都可以用这两个属性实现，实在不够时引入 SVG。

**CSS 边框动画 vs SVG 动画**：CSS border 以 4px 步进增量，产生明显跳跃感；SVG 的路径动画支持亚像素插值，视觉上流畅得多。

#### ② 优先使用 Web Animations API
相比 `requestAnimationFrame`（运行在主线程），Web Animations API 在底层使用 CSS 引擎，可以在合成器线程运行，**HTTP 请求期间动画不会卡顿**。

另一个优势：用 JavaScript 可以引入随机参数（随机延迟、随机持续时长、随机位置），创造更自然的感觉——这在纯 CSS 中无法实现。

```javascript
// Web Animations API 示例（与 CSS 写法几乎一致）
element.animate(
  [{ transform: 'rotate(0deg)' }, { transform: 'rotate(360deg)' }],
  { duration: 1000, iterations: Infinity }
);
```

#### ③ 谨慎使用 `will-change`
`will-change` 告知浏览器提前优化某些属性，但它有副作用：创建新的层叠上下文、消耗大量内存等。

**建议：没有性能问题就不要用。有问题时先彻底理解它的工作原理再用。**

## 七、动效的五大核心价值（总结）

1. **连接状态** — 将用户行为与界面结果建立清晰的逻辑关联，构建可靠的心理模型；
2. **保持方向感** — 通过过渡动画让用户知道自己在界面的哪个位置（而非突然切换）；
3. **引导注意力** — 提示状态变化，或将焦点引向需要关注的内容；
4. **讲述更好的故事** — 以动态方式传递信息和上下文，远比静态截图有效；
5. **提升感知性能** — 让界面感觉更快、更响应，即使底层速度相同。

## 八、Q&A 精华

**Q：设计师需要学代码，开发者需要学设计吗？**

> 代码不是设计师的必修课，设计也不是开发者的必修课。但现在这两个领域的边界正在模糊。如果你做的是 Web 设计或产品设计，了解对方的工作方式会让你更好地沟通、更准确地判断"这件事难不难"。这是协作上的净收益。

**Q：你们用工具生成这些动画吗？**

> 我是个控制狂。我只写我真正需要的代码，自己动手实现每一个效果。不是因为工具不好，而是我喜欢这个过程。自己搞清楚怎么做让我着迷。

**Q：用代码替代视频/图片是否改善了可访问性？**

> 不是必然的。你可以让动画可访问，也可以让它完全不可访问；视频同理。关键不在于用了什么技术，而在于你**怎么用**。没有任何 Web 技术本身是邪恶的。

**Q：Stripe 的这些设计细节算是一种营销手段吗？**

> 主要原因是我们就是喜欢做这些。但确实有一个很好的副作用：当用户看到营销页面如此精心打磨，他们会自然地推断——"如果他们在这里花了这么多心思，产品的其余部分一定也很棒。"这种信任建立是自然发生的，但很有价值。

## 核心精炼

结论：动效的本质是**在用户行为与界面结果之间建立可信赖的因果关系**；所有其他价值（叙事、引导、愉悦感）都从这个根部生长出来。

**_真正克制的动效，不是你注意到它有多精彩，而是你感受到界面有多自然。_**

支柱：

- **因果连接**：动效首要功能是让"做了什么"和"发生了什么"之间产生可见的、可理解的逻辑链——缺失此功能的动效只是装饰，无法构建心理模型。
- **感知即现实**：界面感觉快不快、流不流畅，比实际性能数字更重要；缓动曲线、帧稳定性、动画时机决定感知，而非毫秒数。
- **工艺即文化**：精雕细琢的前端细节不只是美学选择，它向用户传递"我们对整个产品的态度"，是最难模仿的品牌资产。
