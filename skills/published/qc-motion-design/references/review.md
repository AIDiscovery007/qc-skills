# 审查与验证

明确目标组件与交互范围，按改动选择检查场景。观察实际操作中的反馈、节奏和中断行为，再结合源码定位原因。

## 交互检查

| 场景 | 执行的检查 | 通过条件 |
| --- | --- | --- |
| 初次操作 | 触发目标控件并观察状态变化。 | 控件立即回应，最终状态与操作结果一致。 |
| 高频路径 | 重复执行高频操作。 | 动效不排队，不累积等待，不阻塞输入。 |
| 快速反向 | 在过渡中再次切换目标状态。 | 元素从当前状态转向新目标，不闪回旧起点。 |
| 原点与方向 | 改变锚定位置或反向导航。 | 浮层原点对应触发器，进入、返回与关闭保持空间关系。 |
| 键盘路径 | 使用目标控件支持的 Tab、方向键、Enter、Space 与 Esc。 | 控件完成等效操作，不强迫手势，不等待装饰动画。 |
| 焦点生命周期 | 按组件语义测试打开、关闭与后续导航。 | 隐藏内容不可聚焦；需要恢复焦点时，返回有效触发器或新任务目标。提示关闭或焦点已自然移至其他有效控件时，不抢回焦点。 |
| 减少动态效果 | 模拟或启用对应媒体偏好，并触发同一操作。 | 非必要运动消失，文字反馈、业务结果与可操作性保留。 |
| 拖拽取消 | 测试越界、快速轻甩、额外触点与指针取消。 | 元素不跳到新触点，不误提交，取消后状态明确。 |
| 长按确认 | 测试提前松开、失焦、页面隐藏、捕获丢失、额外触点、达到阈值和后续 click。 | 提前松开不提交，完成操作只提交一次。 |
| 提示与通知 | 测试相邻提示切换，以及通知计时的暂停条件。 | 提示按预期跳过延迟，通知不因用户阅读而丢失。 |
| 内容与视口变化 | 使用长文本和窄视口检查组件。 | 无意外溢出或裁剪；必要的容器滚动明确且可操作，焦点提示可见。 |
| 异步与卸载 | 测试真实失败、组件移除和重复请求。 | 视觉状态不伪造成功，卸载后没有残留更新或重复提交。 |
| 性能问题 | 复现负载，并检查掉帧、布局与绘制。 | 优化结论具有实际测量依据，而非仅依赖 API 名称。 |

可放慢动画检查原点、重影与节奏；在交付前恢复正式时长。
只把已执行且有结果的检查标记为通过。将无法执行的设备或状态检查标记为未验证。

## 输出

实现任务：简述动效与反馈变化、设计原因、验证结果和影响使用的限制。
设计或解释任务：按“用户操作 → 组件变化 → 用户理解”说明动效，不默认输出代码审查表。
审查任务：优先报告阻塞输入、错误反馈、中断失败与无障碍问题，再报告节奏和空间关系问题；用表格呈现修改建议。

| Before | After | Why |
| --- | --- | --- |
| `.menu { transition: all 400ms ease-in; }` | `.menu { transition: transform 180ms var(--ease-out), opacity 180ms var(--ease-out); }` | 仅用于允许过渡的指针路径；键盘与即时切换路径取消过渡。 |
| 键盘打开命令面板后等待入场动画 | 键盘打开命令面板后立即输入 | 高频入口不增加装饰性等待。 |

将示例替换为目标代码中的真实证据，并在需要时附文件路径与行号。
不为迎合表格格式虚构问题；没有发现问题时，直接说明审查结果。
用户指定其他交付格式时，采用用户格式。

依据：S1「Review Format」「Review Checklist」「Debugging Animations」；S3「6.1 ① 动效要有用」。取消、焦点与生命周期检查属于工程补充，见 [sources.md](sources.md)。
