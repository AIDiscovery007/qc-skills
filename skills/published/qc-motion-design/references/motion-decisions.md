# 动效决策

在选择动画前，先判断目标操作是否需要等待或视觉解释。

## 频率与目的

| 条件 | 对目标组件执行的动作 |
| --- | --- |
| 用户通过键盘触发状态切换 | 立即提交可确定的状态；取消该次切换的装饰性过渡。 |
| 用户每天执行数百次操作 | 移除命令面板、快捷操作等入口的进出动画。 |
| 用户每天执行数十次操作 | 移除重复动效，或将反馈压缩到不打断操作的程度。 |
| 用户偶尔打开弹层或接收通知 | 使用短过渡解释出现位置与状态变化。 |
| 用户首次引导、提交低频反馈或达成里程碑 | 可加入轻微趣味反馈；不延迟操作完成。 |

这些频率是选择依据，不是需要收集用户行为数据的统计门槛。
对未知频率采用克制的默认方案，不为获取频率额外增加埋点。
键盘操作中的真实异步任务仍需等待结果；立即显示等待状态，不伪造业务成功。

为每个保留的动效写出因果关系：用户执行什么动作，哪个元素发生什么变化，变化帮助用户理解什么。
删除只有“看起来酷”这一理由的高频动效。
只在动图能比静态内容更准确地表达关系或过程时，为说明性图形添加运动。

## 缓动

按交互目的选择曲线，不按 CSS 属性分类。出入场即使包含位移或缩放，也采用出入场规则；只有已显示元素在界面内转换位置或形态时，才采用状态连接规则。

| 目标行为 | 采用的默认方式 |
| --- | --- |
| 元素进入或退出界面 | 使用先快后慢的曲线，让界面立即回应输入。 |
| 已显示元素在界面内转换位置或形态 | 使用先慢、后快、再慢的曲线，连接起止状态。 |
| 元素发生轻微悬停或颜色变化 | 先复用项目的微交互曲线；缺省时可使用 `ease`。 |
| 指示器表达匀速进度或持续旋转 | 可使用 `linear`，避免曲线扭曲速度或进度含义。 |
| 元素响应用户拖拽 | 让元素直接跟随指针；按需为释放后的回弹使用弹簧。 |

优先复用项目中的合适曲线。项目没有动效变量时，可采用以下起点：

```css
:root {
  --ease-out: cubic-bezier(0.23, 1, 0.32, 1);
  --ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
  --ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);
}
```

不为普通响应式 UI 选择开头缓慢的 `ease-in`。
不把 `linear` 用作弹窗、菜单或普通状态切换的默认曲线。

## 时长

| 目标元素 | 采用的起始范围 |
| --- | --- |
| 按钮按压反馈 | 100–160ms |
| 提示与小浮层 | 125–200ms |
| 下拉菜单与选择器 | 150–250ms |
| 模态框与抽屉 | 通常 200–300ms；大幅移动可按实际需要延长至 500ms |
| 连续首次入场的元素 | 每项延迟 30–80ms；仅在顺序有助于理解时启用 |
| 说明性动画 | 按信息理解所需时间选择时长，不套用微交互上限。 |

将常规 UI 的过渡优先控制在 300ms 内。长按确认的等待时间属于操作语义，不属于此上限。
在界面响应阶段优先缩短反馈时间，在用户审慎确认阶段保留必要等待。
不让退出动画拖延焦点恢复，也不让错峰入场推迟元素的可操作时间。

## 感知与整体一致性

用真实结果、及时反馈和稳定节奏改善感知速度，不用转速变化伪装已完成的进度。
让同一产品中的相似组件共享时长、曲线与运动幅度。
先让状态反馈清楚、内容位置稳定，再用动效补充状态间的关系。
把“值得信赖”和“容易理解”作为判断细节的依据，不把某种配色、字体或布局绑定为本 skill 的默认风格。
