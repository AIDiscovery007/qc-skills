# 工程实现

## 实现机制

| 需求 | 选择的机制 |
| --- | --- |
| 用户可能快速反转的状态过渡 | 优先使用 CSS transition，使浏览器从当前值过渡到新目标。 |
| 一次性、预先定义的说明序列 | 可使用 CSS keyframes；避免因重挂载而反复重播。 |
| 需要暂停、取消或动态参数的动画 | 可使用 Web Animations API，并管理动画实例的生命周期。 |
| 需要保留速度的拖拽释放 | 优先使用项目已有的弹簧机制；项目没有机制时，评估新增依赖是否必要。 |
| 元素首次加入 DOM | 在目标浏览器支持时使用 `@starting-style`；否则使用显式挂载状态作为回退。 |

显式列出需要过渡的属性，不使用 `transition: all`。
把状态更改与可选动画分离，使减少动态效果、取消动画或组件卸载都不破坏业务结果。
在组件销毁时清理定时器、监听器、指针捕获与未完成的动画实例。
让中断后的动画朝向最新状态，不要求用户等待旧动画结束。

## 渲染成本

- 优先动画化 `transform` 和 `opacity`，以减少触发布局与绘制的机会。
- 动画确实需要 `clip-path`、`filter` 或布局属性时，缩小影响区域，并在目标浏览器验证帧稳定性。
- 不把 CSS、WAAPI、SVG 或某个库名称当作合成器加速的保证；属性、图层、浏览器与运行条件共同影响性能。
- 项目使用动画库时，检查当前版本与实际执行路径，不照搬历史文档对简写属性的绝对结论。
- 拖拽频繁更新位置时，优先更新目标元素的 `transform`，避免频繁修改大子树根节点上的继承变量。
- 没有实测性能问题时，不添加 `will-change`；确需使用时，限制图层范围并在交互结束后释放提示。
- 集中读取几何信息后再写入样式，避免同一帧内交替读写造成强制布局。

## 弹簧与直接操作

根据阻尼、刚度与质量调节回弹，不把某个库的参数解释成跨库标准。
项目使用时长与弹性参数时，可将较低弹性作为起点；原文的 `bounce: 0.1–0.3` 只用于适合轻微趣味的场景。
用户直接拖动功能性控件时，优先保证位置准确跟手。装饰性指针跟随需要滞后感时，才加入弹簧插值。
在中断测试中检查位置和速度是否连续，而不是仅检查最终位置。

## 无障碍与输入方式

- 优先复用原生控件或项目中已验证的组件，为控件提供名称、角色、状态与焦点路径。
- 让键盘操作直接设置目标状态，只跳过由该次输入触发的装饰动画，不无差别终止页面中其他组件的生命周期。
- 用户启用 `prefers-reduced-motion` 时，移除非必要位移、缩放、旋转、视差与循环运动；保留必要文字反馈和适度透明度变化。
- 同时为 CSS 动画和程序化动画提供减少动态效果路径，并响应偏好在会话中的变化。
- 把鼠标悬停效果限制在支持悬停且指针精确的设备上，避免触屏点击遗留悬停状态。
- 让等待、完成和错误状态具有文字或语义反馈，不仅依赖运动、颜色或声音。
- 指针交互被取消时，将控件恢复到明确状态，并让键盘与触摸路径得到等效结果。

```css
/* 此示例假定组件用 opacity 区分显示状态，用 transform 补充空间反馈。 */
@media (prefers-reduced-motion: reduce) {
  .popover {
    transition: opacity 120ms ease;
  }
  .popover[data-state="closed"],
  .popover[data-state="open"] {
    transform: none;
  }
}
```

将上述选择器替换为目标组件的实际状态选择器；保留隐藏、焦点隔离和指针禁用规则。键盘或其他需要即时切换的路径仍取消过渡，不让此示例重新启用淡化。

## 验证范围

根据改动选择桌面、窄屏、触摸、键盘和减少动态效果场景，不为静态文字修改运行全部交互检查。
在真实设备上验证依赖触摸手势的关键行为；无法访问设备时，明确区分仿真结果与真机结果。
具体检查与交付格式见 [review.md](review.md)。
